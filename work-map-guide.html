문서화 시 주의한 점
DB 설명은 schema.sql 과 Sequelize 모델 파일을 함께 비교해 작성했다. 일부 테이블은 스키마 파일과 모델 정의가 완전히 같지 않아서, 후임 개발자는 운영 DB 구조를 별도 확인하는 것이 안전하다.

현재 문서에서 명확히 확인한 사실

  • 활성 라우트는 frontend/src/Main.jsx 기준으로 홈, 스토리, 심리테스트, 일기장, 밸런스게임, 마스코트 소개다.
  • 백엔드는 /api/test, /api/diary, /api/balance, /api/item 라우트를 등록한다.
  • /api/item 은 구현되어 있지만, 현재 활성 프런트 라우트에서는 직접 연결된 화면을 확인하지 못했다.
  • 좋아요와 선택 결과 일부는 쿠키를 사용해 브라우저 기준 상태를 유지한다.

코드와 문서가 어긋날 수 있는 부분

  • schema.sql 의 back_diary 정의에는 diary_ip, diary_browser 가 없지만, 모델과 컨트롤러는 해당 필드를 사용한다.
  • back_test 도 SQL 파일과 Sequelize 모델의 컬럼 구성이 다르다.
  • 루트 src 폴더에는 별도의 옛 React 코드가 남아 있어, 새 작업 전 어떤 앱이 실제 배포 기준인지 먼저 확인해야 한다.
